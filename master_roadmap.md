# LIFE SAVER Master Roadmap

## Mission
Build real proof in AI, automation, and cybersecurity over 12 weeks through shipped projects, honest execution tracking, and internship-focused packaging.

Phase 1: Foundation and Execution Discipline
Phase 2: Flagship Project Buildout
Phase 3: Packaging, Outreach, and Conversion

## Identity
B.Tech CSE (Cybersecurity) student building AI tools, automation systems, and security-aware applications.

## Core System
- LIFE SAVER is the execution system.
- PromptShield is the flagship AI + cybersecurity project.
- Internship Copilot Lite is the supporting AI + automation project.

## Phase 1: Foundation and Execution Discipline
Goal: build the execution system, ship the first security-aware AI tool, and create a stable working rhythm.

### Week 1
Theme: Build the execution system
Goal: Ship the first working version of LIFE SAVER.
Success Definition:
- LIFE SAVER runs locally.
- SQLite is connected.
- Daily check-in works.
- Weekly roadmap page is visible.
- Mission and week data are entered.
Deliverables:
- Working local LIFE SAVER app
- Four core pages
- SQLite schema
- First saved daily check-in
- Week 1 task seed
- Weekly review page

### Week 2
Theme: First cyber-aware AI tool
Goal: Build PromptShield v0.
Success Definition:
- PromptShield runs locally.
- The app accepts risky text or prompts.
- The app returns risk score, verdict, and matched patterns.
- At least 10 sample inputs produce different outputs.
Deliverables:
- PromptShield local app
- Four basic risk categories
- Sample case dataset
- Rule-based detectors
- Risk scoring and verdict system
- Honest README

### Week 3
Theme: Explainable and safer PromptShield
Goal: Add AI-assisted explanation, redaction, and scan history.
Success Definition:
- Rule-based and AI-assisted reasoning both work.
- Sensitive content is redacted before model analysis.
- Scan history persists.
- Result flow shows score, categories, why, action, and safer guidance.
Deliverables:
- Modular PromptShield structure
- Scan history
- Optional AI explanation layer
- Redaction flow
- Safer result UX
- Stronger test set

### Week 4
Theme: Lock the foundation
Goal: Stabilize LIFE SAVER and PromptShield and improve public positioning.
Success Definition:
- LIFE SAVER is usable every day without friction.
- PromptShield can be demoed in three to five minutes.
- GitHub profile clearly reflects AI + automation + cybersecurity.
- First resume draft exists.
Deliverables:
- Improved LIFE SAVER usability
- Codex context export
- More stable PromptShield
- Updated GitHub profile
- Resume v1
- Demo and explanation notes

## Phase 2: Flagship Project Buildout
Goal: turn PromptShield into a real flagship project that is structured, explainable, and internship-grade.

### Week 5
Theme: API-first security console
Goal: Turn PromptShield into a usable security console with persistence and review flow.
Success Definition:
- Text can be scanned through UI or API.
- Saved scans appear in a queue.
- Detail view explains how a verdict was reached.
- Analyst review states can be updated.
Deliverables:
- API routes
- Saved scan records
- Incident queue
- Incident detail page
- Analyst review workflow
- Test harness

### Week 6
Theme: Real-world input expansion
Goal: Expand PromptShield to more realistic input types.
Success Definition:
- PromptShield supports at least two input modes.
- Email-style content is analyzed differently from generic prompts.
- Input mode is stored and shown in results.
- File or large-text input works for simple cases.
Deliverables:
- Input mode selection
- Email-focused detection
- Mode-aware explanations
- Simple text file support
- Realistic scenario testing

### Week 7
Theme: Reviewable, reportable, and tunable
Goal: Make PromptShield feel like a mini analyst workstation.
Success Definition:
- Overview dashboard shows real summary metrics.
- Analyst notes are richer than a simple status.
- Incident reports can be exported.
- Score tuning is configurable and explainable.
- Failure handling is stronger.
Deliverables:
- Overview dashboard
- Improved analyst review fields
- Report export
- Tuning config
- Better error handling
- Stronger README and screenshots

### Week 8
Theme: Flagship packaging
Goal: Make PromptShield internship-grade and portfolio-ready.
Success Definition:
- PromptShield works end to end.
- README, architecture story, and demo flow are clear.
- The project can sit at the top of the resume.
- Limitations and future improvements are documented.
Deliverables:
- PromptShield v1
- Polished README
- Architecture or case study doc
- Demo asset
- Stronger GitHub positioning
- Updated resume bullets

## Phase 3: Packaging, Outreach, and Conversion
Goal: package the work, apply to roles, improve outreach, and close the sprint with proof and clarity.

### Week 9
Theme: Package for the market
Goal: Turn projects into internship-ready public proof.
Success Definition:
- Resume v2 exists.
- GitHub profile is clearer.
- Simple portfolio or proof page exists.
- LIFE SAVER tracks internship actions.
- First targeted application batch is sent.
Deliverables:
- Positioning statement
- Resume v2
- Improved GitHub profile
- Portfolio or proof page
- Internship tracker
- First targeted application batch

### Week 10
Theme: Build a lightweight support automation tool
Goal: Ship Internship Copilot Lite to support real internship applications.
Success Definition:
- The tool accepts a job description and fixed candidate profile.
- It returns role fit, missing gaps, best project to highlight, and a tailored intro.
- The tool is used on at least three real roles.
- It supports actual applications.
Deliverables:
- Internship Copilot Lite
- Job-fit logic
- AI-assisted tailored intro generation
- Three real-job analyses
- LIFE SAVER integration note
- Second application batch

### Week 11
Theme: Convert projects into opportunities
Goal: Improve role targeting, outreach quality, and interview readiness.
Success Definition:
- Role buckets are defined.
- Message templates exist.
- PromptShield and LIFE SAVER can be explained clearly in interview style.
- Another meaningful application batch is sent.
- Last major weak spots are identified and improved.
Deliverables:
- Role bucket strategy
- Outreach templates
- Interview explanation sheets
- High-impact weak spot fixes
- Application batch three and follow-ups

### Week 12
Theme: Finish the sprint like a professional
Goal: Close the 12-week sprint with visible proof and a clear next step.
Success Definition:
- Core assets are polished enough to share confidently.
- Full 12-week review is complete.
- Final application batch is sent.
- Next 30-day continuation plan is defined.
- Final identity and direction are clear.
Deliverables:
- Final polished assets
- Final resume and public profile package
- Final application batch
- Full 12-week reflection
- Next 30-day continuation plan
- Sprint closeout export
